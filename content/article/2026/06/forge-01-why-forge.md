最近这段时间，Coding Agent 已经从一个很酷的演示，变成了很多开发者日常工作流的一部分。我们把需求交给它，让它读代码、改文件、跑测试、修报错，甚至继续拆任务给别的 agent。表面上看，这像是一次模型能力的跃迁；但真正使用久了以后会发现，决定体验好坏的往往不是某一次回答有多聪明，而是它背后那套运行机制是不是可靠。

这也是我做 Forge 的原因。

Forge 不是为了再造一个生产级 Coding Agent。它更像一个教学用的剖面模型：把一个 agent 的核心结构拆开，做成足够小、足够清楚、可以本地运行、可以观察每一步的系统。我的目标不是让读者相信“Agent 很神奇”，而是让读者亲眼看到：Agent 到底如何循环，如何拿上下文，如何决定调用工具，如何把工具结果塞回对话，如何被验证器打回，如何在出错后继续修正。

# 从“会用”到“看懂”

很多人已经会用 Agent，但不一定看懂 Agent。

会用，意味着你知道如何写一个任务描述，知道什么时候让它继续，知道失败时重新提示它。看懂，则意味着你能回答这些问题：

- 它为什么会知道该读哪个文件？
- 它为什么能调用工具，而不是只输出一段文字？
- 它怎么判断自己完成了？
- 如果它说完成了，但测试没过，系统应该怎么办？
- 长任务跑到一半断掉，状态保存在哪里？
- 上下文越来越长，哪些内容应该留下，哪些应该折叠？
- 外部工具、技能包、多 agent 协作应该怎样接进来？

这些问题听起来像实现细节，但它们其实决定了 Agent 是否可教学、可调试、可信任。

如果一个 Agent 只是黑盒，学习者最多学会一套使用技巧；如果它的内部过程是透明的，学习者就能逐渐建立一种新的工程直觉：Agent 不是一个会说话的函数，而是一个由模型、上下文、工具、执行环境、验证器和日志共同组成的运行系统。

# Forge 想保留复杂性，但去掉噪音

Forge 的设计目标很克制：只保留理解 Agent 必须要看的复杂性。

所以它从一个最小闭环开始：

```text
Task
 ↓
Agent Runner / Loop
 ↓
Context Builder
 ↓
Model
 ↓
Tool Executor
 ↓
Trace & Evaluation
```

这里没有庞大的平台，没有复杂的 UI，也没有生产系统里那些必须但容易遮住重点的工程设施。Forge 一开始只做一件事：让一个本地 Coding Agent 能够接收任务、调用工具、修改代码、运行验证，并把全过程记录下来。

在这个最小闭环上，我逐步加了十个版本：

- v0.1：最小 Agent Loop 和 7 个核心编码工具
- v0.2：Verifier gatekeeper 和自我修复循环
- v0.3：任务套件和隔离 workspace，用来评估 Agent
- v0.4：Checkpoint 和 Resume，让长任务可以中断恢复
- v0.5：Planning / Replanning，让计划显式可见
- v0.6：Context Compiler，把长历史压缩成可用上下文
- v0.7：Sandbox 和执行边界，限制危险命令和路径访问
- v0.8：MCP stdio client，让外部工具动态接入
- v0.9：Skill Bundle，让认知规则和工具包热加载
- v0.10：Subagents，让父 Agent 并发委派子任务

这条演进线不是为了堆功能，而是为了回答一个教学问题：如果我们从零开始解释 Agent，哪些能力必须一层一层出现？

# Agent 教育不该只教 Prompt

过去一段时间，很多 AI 教育都停留在 prompt 技巧：如何写角色、如何给背景、如何约束输出格式。这些当然有用，但如果只停在这里，学习者很容易形成一种错觉：Agent 的能力主要来自“更会说话”。

可真正的 Agent 系统不是靠一段 prompt 撑起来的。

它需要工具协议，才能从“回答问题”变成“执行任务”；需要验证器，才能避免模型自己宣布胜利；需要 trace，才能复盘每一步为什么发生；需要上下文编译器，才能在长任务里保住关键信息；需要 sandbox，才能让本地执行有边界；需要技能系统和 MCP，才能持续扩展；需要 subagents，才能把复杂任务拆给不同角色并行处理。

这些东西组合起来，才是 Agent Literacy：理解、监督、约束和构建 Agent 的能力。

Forge 想教的正是这个。

# 这组文章会怎么写

我会按 Forge 的版本演进来写，但每篇不会只是版本日志。每篇都会围绕一个问题展开：

1. 这个问题为什么在 Agent 系统里必然出现？
2. Forge 里用什么最小实现展示它？
3. 对学习者来说，这个机制建立了什么直觉？

换句话说，这组文章不会把 Forge 包装成一个万能产品，而是把它当作一张可以动手拆装的 Agent 教学地图。读完以后，如果你再去看 Codex、Claude Code、Gemini CLI、OpenHands 或任何别的 Agent 工具，看到的就不只是界面和输出，而是它背后那些熟悉的结构：loop、context、tool、trace、verifier、sandbox、skills、subagents。

这就是 Forge 的出发点：把魔法还原成工程，把工程重新变成可以学习的东西。
